| Код    | Требования                                                                                                                                                                                                                                                                                         |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **F**  | **Функциональные (Functionality)**                                                                                                                                                                                                                                                                 |
| F1     | Сайт разрабатывается для неавторизованных потенциальных клиентов, а интернет-банк для идентифицированных клиентов банка.                                                                                                                                                                           |
| F2     | Клиент видит на сайте список доступных депозитов с актуальными ставками. Клиент может подать заявку на депозит, оставив свои номер и ФИО.                                                                                                                                                          |
| F3     | Менеджер кол-центра должен видеть заявки новых клиентов и оставленные данные и звонить по ним. Он должен быстро или автоматически вычислять ставку и особые условия для клиента.                                                                                                                   |
| F4     | Новым клиентам необходимо прийти в отделение банка для идентификации.                                                                                                                                                                                                                              |
| F5     | Клиент видит в интернет-банке список доступных депозитов с актуальными ставками и персонализированными ставками. Клиент может оставить заявку на открытие депозита, указав счет-источник и сумму.                                                                                                  |
| F6     | Операция открытия депозита в интернет-банке должна быть подтверждена клиентом с помощью СМС-кода.                                                                                                                                                                                                  |
| F7     | Сотрудники бэк-офиса должны иметь возможность подтвердить условия и открыть депозит в АБС на основании одобренной заявки.                                                                                                                                                                          |
| F8     | Система АБС должна позволять сотрудникам бэк-офиса смотреть ставки по депозитам и кредитам из XLS-файлов через веб-интерфейс. Сотрудники кредитования должны раз в день загружать обновленные XLS файлы в систему АБС.                                                                             |
| F9     | Система АБС должна автоматически отправлять СМС-уведомления клиенту: после подтверждения ставки менеджером и после успешного открытия депозита.                                                                                                                                                    |
| **U**  | **Удобство использования (Usability)**                                                                                                                                                                                                                                                             |
| U1     | Клиентские интерфейсы (сайт, интернет-банк) должны строго соответствовать системе дизайна и брендбуку банка.                                                                                                                                                                                       |
| U2     | При длительных операциях интерфейс должен показать пользователю, что происходит и просить подождать, например с помощью скелетонов.                                                                                                                                                                |
| U3     | Процесс подачи заявки должен быть максимально упрощён и содержать минимальное количество шагов.                                                                                                                                                                                                    |
| **R**  | **Надёжность (Reliability)**                                                                                                                                                                                                                                                                       |
| R1     | Общая доступность системы интернет-банка и связанных сервисов должна составлять 99.9% (24/7).                                                                                                                                                                                                      |
| R2     | В случае сбоя в основном ЦОД необходимо обеспечить переключение на резервный ЦОД с минимальным временем простоя.                                                                                                                                                                                   |
| R3     | Архитектура должна предусматривать горизонтальное масштабирование сервисов интернет-банка для распределения нагрузки. Для этого используем Kubernetes                                                                                                                                              |
| **P**  | **Производительность (Performance)**                                                                                                                                                                                                                                                               |
| P1     | Время отклика на любые UI-операции (просмотр списка депозитов, подача заявки) не должно превышать 50 мс. При загрузке большого объема данных интерфейс не должен зависать и должен показать пользователю, что происходит загрузка.                                                                 |
| P2     | Необходимо устранить проблему медленной загрузки справочных данных (более 1 секунды).                                                                                                                                                                                                              |
| **S**  | **Поддерживаемость (Supportability)**                                                                                                                                                                                                                                                              |
| S1     | **Выбор технологий:** При выборе технологий необходимо отдавать предпочтение уже используемым в банке (например, БД: MS SQL, Oracle). Новые технологии должны быть совместимы с существующими платформами, а у сотрудников должна быть хотя бы базовая экспертиза по ним (языки программирования). |
| S3     | **Архитектура:** Необходимо предусмотреть постепенный переход интернет-банка на микросервисную архитектуру, начиная с сервиса депозитов. Для асинхронной коммуникации между сервисами предпочтительнее использовать Kafka (на перспективу - текущая платформа не совместима с ней).                |
| S3     | **Документация:** Необходимо поддерживать документацию для дальнейшего расширения системы                                                                                                                                                                                                          |
| **+R** | **+ Ограничения (Restrictions)**                                                                                                                                                                                                                                                                   |
| R1     | **Защита чувствительных данных:** Весь трафик (клиент-сервер и между сервисами) должен быть защищён с помощью современных механизмов шифрования (TLS).                                                                                                                                             |
| R2     | **Идентификация:** Новые клиенты, пришедшие с сайта, обязаны пройти очную идентификацию в отделении банка.                                                                                                                                                                                         |
| R3     | **SMS-функционал:** Нежелательны доработки ядра системы (платформы подрядчика). Функционал отправки SMS должен быть реализован силами IT-отдела банка через создание отдельного сервиса, взаимодействующего напрямую с телеком-оператором.                                                         |
| R4     | **Нагрузка на АБС:** Прямые запросы от всех сервисов к API АБС запрещены. Взаимодействие должно осуществляться через асинхронный буфер (очередь сообщений).                                                                                                                                        |
